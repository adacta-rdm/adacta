title: Core concepts
---

Adacta represents equipment, working places, samples, source files, and recorded data as separate real-world objects. It then records the relationships among them so that research data remains understandable and searchable. This page provides a short glossary; follow the links for fuller explanations. {% .lead %}

{% callout title="Evolving terminology" %}
The term **facility** is planned to be replaced, and **station** is the working name while the final choice is made. Current interface labels and existing manual pages may still use **facility**.
{% /callout %}

## Equipment and stations

| Concept                   | Short description                                                                                                                                                                                                                    | Learn more                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| **Manufacturer**          | The organization that makes or supplies catalog products.                                                                                                                                                                            | [Catalog](/docs/catalog)                                                          |
| **Product**               | A catalog definition for a make and model of equipment. It describes what all physical items of that product have in common.                                                                                                         | [Catalog](/docs/catalog)                                                          |
| **Product capability**    | Something a product can do, and therefore something its physical items can do. Recording data through a channel is one kind of capability.                                                                                           | [Planned data import](/docs/planned-data-import#channels-as-product-capabilities) |
| **Channel**               | A data-oriented product capability, such as actual flow, requested flow, temperature, valve position, or CO2 concentration. A channel has a stable key, name, description, role, value type, and, where applicable, a quantity kind. | [Planned data import](/docs/planned-data-import#channels-as-product-capabilities) |
| **Inventory item**        | One particular physical object, such as an MFC with a specific serial number. An item is an instance of a product and receives its available capabilities from that product.                                                         | [Inventory and facilities](/docs/inventory-and-facilities)                        |
| **Station**               | One standalone experimental device with a location, such as a catalyst test stand or a characterization instrument. A sample is taken to a station to obtain a result. The current interface calls this a facility.                  | [Stations](/docs/stations)                                                        |
| **Location**              | Where a station physically resides, such as a building, floor, room, or another description meaningful to the research group. Several stations can share one location.                                                               | [Stations](/docs/stations)                                                        |
| **Station configuration** | The time-valid description of the items, connections, and samples present at a station. The current interface calls this a facility state.                                                                                           | [Facility flowcharts and states](/docs/flowcharts-and-states)                     |
| **Station slot**          | A stable functional position in a station configuration, such as `MFC-4`, which may be occupied by different physical items over time.                                                                                               | [Facility flowcharts and states](/docs/flowcharts-and-states)                     |
| **Tag**                   | A named classification. Tags marked **PID** provide the vocabulary for nodes in station configuration diagrams.                                                                                                                      | [Tags](/docs/tags)                                                                |

## Samples and research context

| Concept          | Short description                                                                                                                                                      | Learn more                                                                          |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **Sample batch** | Material sharing a common preparation history. Data from synthesis, characterization, activation, and testing can be found together through the batch.                 | [Samples and batches](/docs/samples-and-batches)                                    |
| **Sample**       | A physical portion of a sample batch that can be installed in a station or used in a particular operation.                                                             | [Samples and batches](/docs/samples-and-batches)                                    |
| **Context**      | The relationships that explain data, including the station, physical items, users, samples, sample batches, and applicable time intervals.                             | [Planned data import](/docs/planned-data-import#drop-location-and-resolved-context) |
| **Experiment**   | A useful view over related lifecycle data. It need not be a rigid container: it may be a saved selection by sample batch, time range, station, user, or other context. | [Planned data import](/docs/planned-data-import#finding-lifecycle-data)             |

## Files, importing, and recorded data

The concepts in this section describe the planned import model. They are not yet available as a complete workflow.

| Concept              | Short description                                                                                                                                                                                 | Learn more                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **Resource**         | The current application term for a managed file or dataset. The planned model distinguishes original source artifacts from materialized datasets.                                                 | [Resources](/docs/resources)                                                                             |
| **Source bundle**    | The original group of files supplied together for one import, such as measurement data, a sidecar, calibration information, and notes.                                                            | [Source bundles](/docs/planned-data-import#source-bundles)                                               |
| **Source artifact**  | One preserved file within a source bundle. Its role may be data, manifest, calibration information, or documentation.                                                                             | [Source bundles](/docs/planned-data-import#source-bundles)                                               |
| **Data sidecar**     | An optional, portable description supplied beside data or through the API. It can identify columns, channels, units, equipment, and other context.                                                | [Sidecars and UI-assisted descriptions](/docs/planned-data-import#sidecars-and-ui-assisted-descriptions) |
| **Import preset**    | Reusable rules for interpreting files that repeatedly use the same structure.                                                                                                                     | [Sidecars, plans, and presets](/docs/planned-data-import#sidecars-plans-and-presets)                     |
| **Import plan**      | The validated interpretation for one particular import, including supplied identifiers and the Adacta objects to which they resolved.                                                             | [Sidecars, plans, and presets](/docs/planned-data-import#sidecars-plans-and-presets)                     |
| **Importer**         | Format-specific behavior that recognizes, previews, inspects, and eventually materializes a source. Different complex formats can have focused importers instead of sharing one universal wizard. | [How importers help](/docs/planned-data-import#how-importers-help)                                       |
| **Dataset**          | A logical group of axes and recorded channels produced by an import or transformation. It is linked to, but distinct from, the original source bundle.                                            | [Datasets and recorded channels](/docs/planned-data-import#datasets-and-recorded-channels)               |
| **Axis**             | A coordinate on which recorded values depend, most commonly time. A dataset may contain more than one axis.                                                                                       | [Quantity kinds, units, and axes](/docs/planned-data-import#quantity-kinds-units-and-axes)               |
| **Recorded channel** | The values recorded from one product channel of one physical inventory item within a dataset.                                                                                                     | [Datasets and recorded channels](/docs/planned-data-import#datasets-and-recorded-channels)               |
| **Quantity kind**    | What a value represents physically, such as temperature, pressure, or volume flow rate.                                                                                                           | [Quantity kinds, units, and axes](/docs/planned-data-import#quantity-kinds-units-and-axes)               |
| **Unit**             | The scale in which a quantity is expressed, such as kelvin, bar, or millilitres per minute.                                                                                                       | [Quantity kinds, units, and axes](/docs/planned-data-import#quantity-kinds-units-and-axes)               |
| **Provenance**       | The traceable history connecting original files, supplied metadata, user decisions, importer software, and resulting datasets.                                                                    | [Preserving provenance](/docs/planned-data-import#preserving-provenance)                                 |

## How the concepts connect

A product describes a kind of equipment and its channels. An inventory item is one physical instance of that product. A station configuration records where the item and any samples were present during a time interval. A source bundle is interpreted by an importer using a sidecar or information supplied through the UI. The resulting import plan creates a dataset whose recorded channels point back to the physical items and product channels that produced them.

Because these objects remain separate, Adacta can organize data by equipment, station, user, sample batch, time range, or any useful combination of those facts.
